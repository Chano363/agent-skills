# Venue Verify（会议真实性与投稿窗口核实）

核实会议能否投：只信一手，逐环验证，按用户硬约束筛选。**未核实的信息一律显式标注"未核实"，禁止当结论输出。**

## 硬约束先行

动手前确认三件事（用户已给则跳过）：① 检索完成截止日（本项目为 2027-06-30）；② 可接受的截稿窗口（留足写作时间）；③ 出版/检索类型（EI/Scopus/核心）。每个候选都要能串成"截稿 → 会期 → 检索完成"的时间链，断链即出局。

## 核实五步（每个候选都走）

1. **截稿日期**：只认会议官网一手页面。聚合站（艾思科蓝、wikicfp、知乎/论坛）仅作线索。**最大陷阱：把"会期"当"截稿"**——12 月开的会通常 9~10 月截稿，必须逐字区分。
2. **出版方归档实证**：IEEE 会议在 IEEE Xplore 按 conference record 查往届（近年是否连续归档）；Springer 查 LNCS/LNEE 系列收录记录。无往届实证的新会/改出版社的会降级标注。
3. **EI 检索实证**：往届是否真被 Compendex 收录——找独立证据（Xplore 页面 EI 标注、已检索论文的检索号、往届作者的检索证明），**运营方自己的"EI 检索截图"不算证据**。
4. **IEEE 会议编号自查**：conferences.ieee.org 能查到该会议编号才可信；查不到的（无论页面多正规）一律不投。
5. **商业链识别**：投稿走 163/126/outlook/QQ 邮箱、模板站、官网 404、无组委会署名、滚动改名系列——命中越多可信度越低，表格里显式标注。

## 输出格式

- **候选表**：会议 | 截稿（含冲突标注）| 会期 | 出版·检索 | 契合点 | 可信度 + 官网链接
- **已排除清单**：每条带出局原因（截稿已过 / 查无实据 / 检索不达标 / 假会嫌疑）
- **结论**：主推 1 个（给理由）+ 备胎 + 当前悬点（如截稿轮待邮件确认）
- 特殊项单列：契合度高但违反硬约束的（如检索晚于截止日），写明突破条件，交给用户决策

## 已验证范例

`traffic_rl_project/docs/杂项/项目介绍和问题简述.md` Q8（2026-10-17 三轮检索：对口档 + 泛主题档，含排除清单与结论段），结构与措辞以其为准。
