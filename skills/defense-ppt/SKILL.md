# 答辩 PPT 大纲·文案·生图规范（中期答辩复盘版）

**背景**：用户自己动手做 PPT 页面，AI 负责大纲文案 + 底稿图。本轮中期答辩（16 页，`traffic_rl_project/ppt_talk/midterm_20261018/答辩PPT结构方案_v3.md`）反复返工，以下每条都对应一次真实翻车。**宁可慢，不可再犯。**

## 0. 铁律总纲（先读这个）

1. **只改用户指定的部分，绝不扩大战果。** 用户说改 P4 右栏，就只动右栏；"顺手"整页重写 = 大忌。
2. **藏拙。** 没做完的工作不上 PPT；将来时只进"下一步计划"页；"（拟）""即将启动"等标注全禁；凡陈述句只写已有产物。
3. **数字必须有归档背书。** 上 PPT 的每个数字必须能在 outputs/ 或文档里指出来源；不可复现的数字、被否决方案的数字、"备注里编造成因"一律不写。**拿不准就不写数字**（定性表述永远安全）。
4. **去黑话。** 项目内部叫法全改全称：ED/AB→电制动/空气制动、"列尾压强就绪度"→列尾充风状态、HIL→硬件在环、"骨架/锁死"等口吻词禁止。
5. **不写"研究空缺"叙事。** 用户是"针对场景用方法解决问题"，不是"为方法找空缺"。禁"尚属空缺/首次/首创"。
6. **事实性说法必须有一手依据。** 写进文献表/文案的每个论断回论文原文或 ADR 核实；已废止说法（如"换线需重建模型"）严禁复活。

## 1. 写大纲

- **页面组织**：按"研究进展"组织进展页（不是"研究内容"），标题句式统一：`研究进展N：构建/建立/搭建兼顾A与B的…`。页底导航条与页内标题必须一致。
- **大纲必须明晰可操作**：用户照抄就能做页。每页给出：版面分区（左/右/上/下占比）→ 每格放什么（文字直接给成品、图片指到具体文件路径）→ 结论条文字。写"配一张图"而不给路径 = 不合格。
- **页面结构沿用**（学姐式）：标题 → 导语（一两行）→ 主体（图/表/分块）→ 底部结论条（红字引导词 + 定性结论）。
- **每页自查**：正文与图内文字口径一致（观测项、指标名逐字对上）；用词全页统一（如"列距"不要混"列间间距"）；标点统一（括号闭合！分隔符、句尾标点各页一致）。

## 2. 写文案（语言风格）

学姐风格三句式（参考 `reference/学姐总体框架图_风格基准.png` 与大纲文档内已定稿段落）：

1. **总起句**：`针对【场景特点】，本研究选择【算法】，研究【方法】` —— 一行红框，不写成长段。
2. **逐项收束**：`以完成…` + 出处标注。
3. **结论条**：`条件限定 + 结论；对比 + 诚实留口（还需继续验证）`。定性优先，分号衔接，各页格式一致。

硬规则：

- 禁公式风：`A＝B＋C＋D`、`电制动调节＋空气制动档位` 这类加号串 → 改顿号或陈述句。
- 禁"·"堆串与浅色小字注（图内、页面都禁）。
- 禁口语字："观测**带**编队上下文"→"观测**引入**"。
- 比较句式 `A under B`；图内文字一律英文（项目生图规范），页面文字中文。
- 平台/硬件描述**必须以用户口述事实为准**：不懂就问清"它是什么、能做什么、和课题什么关系"，绝不脑补升级（小车≠编组验证平台！写错定位会被当众戳穿）。

## 3. 生图（底稿/示意图）

1. **先问清三件事再动手**：① 放页面哪个位置、**留白区宽高比**（横版/竖版，差一点就返工）；② 和页面其他元素的关系（嵌入拼图？独立机制图？）；③ 内容口径（哪些框、哪些箭头、什么标签）。
2. **真数据优先于手绘**：用户原话"人家放的是真实数据图，不是随便编的"。凡有归档数据（trajectory.npz、result.json、现成 png）直接用/拼装；手绘曲线冒充数据 = 编造。机制/框架图（框+箭头）可以画，数据曲线只能出自归档。
3. **现成图直接拼，不要重画**：用户明确说"images 文件夹里不是有吗？你直接拼图不就好了？"——图已存在时用 PIL/matplotlib 载入嵌入，等比居中不变形。
4. **风格基准**：仿 `reference/学姐总体框架图_风格基准.png`——编号色块面板（淡蓝 #EAF1FB/淡橙 #FDF2E2/浅灰蓝 #F7F9FC）、白底藏青描边小框、藏青实心箭头、底部浅绿评价横条（红字标题）、绿虚线闭环。matplotlib 可胜任此风格；python-pptx 原生形状复刻 PPT 质感已被否决（"质感完全不对"），不要再用。
5. **配色 tokens**：NAVY #2F4A7A / RED #C00000 / GREEN #2E7D32 / 上述三淡色面板。字体 Microsoft YaHei，300 dpi，白底。
6. **每版必目检**（Read 输出图再交付），检查清单：
   - 文字全部在框内，无重叠、无遮挡、无越界；
   - 箭头方向语义正确（下发↓回传↑……逐个核对起止点）、箭头与面板留缝不插入；
   - 布局方向与用户留白一致（竖版区域出横版图 = 白干）；
   - 无序号（用户明确要求过去序号）、无浅色小字、无公式串；
   - 图内文字英文（数据图）/中文（机制图按用户页面语言）。
7. **一次只交付用户要的东西**：要"MARL 框架图"就只画框架图，不要顺手加装饰、加宽画布、"加点别的"。用户说加内容时先给建议清单让选，不要自作主张。

## 4. 迭代纪律

- 用户给截图批评时，逐条对照找问题，先说结论改什么，再动手；改完**复述改了哪几处**。
- 同一问题第二次被骂（如箭头方向、比例）说明第 4.6 条目检没做——停下来把清单过一遍再交付。
- 用户情绪化时别解释堆砌，直接改，改完一句话确认。
- 已被否决的路线（python-pptx 原生形状、色块满填仿学姐、手绘数据曲线、随意加宽画布）记入本文件，**永不重试**。
