# Discussion Doc（对外讨论交流文档）

为项目撰写或更新**给外部读者**（老师、学长、学姐、合作者）的讨论文档：项目介绍 + 问题清单。范例与模板参照 `traffic_rl_project/docs/杂项/项目介绍和问题简述.md`。

## 工作流（按序执行）

### 0. 先确认读者身份（动笔前必做）

写之前先向用户确认读者是谁——**项目组成员 / 导师 / 学长学姐**，不同身份颗粒度完全不同；用户已明确指定（如"给学长的"）时跳过此步。

| 读者 | 颗粒度 | 内容重点 | 黑话处理 |
|---|---|---|---|
| 项目组成员 | 最细 | 进度对齐、任务边界、具体数值与命令 | 可用内部代号与 ADR 编号，**不去黑话** |
| 导师 | 中 | 结论与决策：方向、里程碑、资源需求、风险、需拍板项 | 研究术语（MPC、MARL）可用，内部流程词去掉，技术细节折叠成一句话 |
| 学长/学姐（外部合作者） | 最粗 | 自包含介绍（对象/背景/核心观点从头交代）+ 聚焦对方专业的问题清单 | 全部项目独有黑话改直白+括注，只留关键数字 |

已知对方方向时，问题清单按其专业定制：如 RL 方向学长重点问训练稳定性/超参/消融/种子数与显著性；物理方向才展开仿真曲线细节；通用读者才保留读文献方法、分工、会议等通用问题。

### 1. 提取原始材料，保留原件

- 来源是 docx 时：用 `scripts/extract_docx.py` 提取（段落+表格+OMML 公式转 LaTeX+图片），**原件 docx 不动**，md 作为活文档。图片落到 md 同目录的 `<文档名>.assets/` 文件夹。
- 来源已有 md 时：直接在其上修订，头部保留来源说明行（提取自什么、口径以什么为准、更新日期）。

### 2. 对照权威来源核实现状（一手优先）

按顺序核实，**只写文档里有据的内容**；搜不到/查不到的一律标注"未核实"，禁止把推断写成事实：

1. `AGENTS.md`（要点指针、最新决策编号）
2. 决策记录 `docs/logs/decisions/DECISIONS.md`（最新 ADR，注意"已废止/覆盖"关系）
3. 立论文档 `docs/RESEARCH_POSITIONING.md`（研究对象、口径、实验矩阵）
4. `docs/PROJECT_PIPELINE.md` 与 `docs/logs/progress/`、`docs/logs/diagnostics/`（已完成/未完成、最新日期的条目）

更新对象：研究对象与规模、核心观点（注意已被废止的旧 claim 不许复现）、实验矩阵、实验现状（已完成/未完成）、问题清单（旧问题标 ✅已解决并写结论，保留仍有价值的残余提问）。

### 3. 去黑话（面向外部读者的硬规则；组内文档豁免本节，导师/学长学姐按第 0 步颗粒度执行）

- **项目内部代号与缩写**：首次出现必须给直白表述+括注（如"本文方法（简称 D-RL）""ATP（列车超速防护）"）；纯内部流程词（pilot C、闸门、破线、冻结 commit、轮次编号如 A–AG）改写为通俗说法，不留痕。
- **行业通用缩写**（MPC、EI、IEEE）可保留，关键者首次括注。
- **数字与口径保留**：验收线、峰值、检索实证等关键数字是严谨性的载体，不许为通俗而删。
- **删除读者不需要的内部纪律**（防守句式、三项不加、ADR 编号引用等），最多转成一句话的通俗版。
- 称呼与提问对象按目标读者统一（给学长就把"请教"指向学长；历史事实如"学姐推荐的文献"可保留）。

### 4. 结构模板

```
# 项目情况（日期更新）
> 来源说明行（提取自 X，按 Y 现状更新，口径以 Z 为准）

## 一、项目介绍
研究对象（规模+对齐依据） → 核心观点 → 导师给定方向（原文保留） → 后续修正（原文保留）
→ 实验矩阵（表格：组别/场景/方法/说明） → 评价指标 → 对比纪律
→ 实验现状（已完成 bullet 列表 / 未完成 bullet 列表）
→ 图 1..N（图注用陈述式中文，一句一图）

## 二、给 XX 的问题（按现状更新）
逐条：主题（✅已解决 / 进行中 / 无标记=开放）
```

### 5. 图片

- 全部图放 `<文档名>.assets/`，md 内用**相对路径** `![](<文档名>.assets/imageN.png)`（打包发人时可显示）。
- 修复类内容保留"问题证据图"，图注注明"修复前/问题证据"。
- 图内文字规范（英文、轴标签带单位）遵循 `docs/rules/EXECUTION_RULES.md` 生图规范。

### 6. 落盘与登记

- 落 `traffic_rl_project/docs/杂项/`（交流材料区，非研究 SSOT）。
- 新建文档必须在 `docs/README.md` 索引登记（改条目描述即可）。
- 完成后向用户报告：更新了哪些节、标注了哪些"未核实"。

## 校验清单（发布前过一遍）

- [ ] 读者身份已确认，颗粒度与其匹配（组内可留代号；对外无未解释黑话；问题清单按对方专业定制）
- [ ] 每个事实能对上权威来源；"未核实"处已显式标注
- [ ] 无已废止的旧口径复活（对照最新 ADR）
- [ ] 外部读者视角通读一遍：无未解释的内部缩写/代号
- [ ] 图片相对路径在打包后仍有效；原件快照未被修改
- [ ] 索引已登记
