# ESP32-IDF Agent Skill

Use this skill for ESP32 projects built with the ESP-IDF v5.4+ toolchain and the `idf.py` build system. Covers the conda-based environment used in this repo (no IDF venv) and the specific project patterns in `src/esp32/wifi_tx/`.

## Environment Setup

This repo does NOT use the IDF Python virtual environment. Python comes from conda base; build tools come from `IDF_TOOLS_PATH`.

### Environment Variables (effective)

```powershell
$env:IDF_PATH = "E:\ESP-IDF\.espressif\v5.4.4\esp-idf"
$env:IDF_TOOLS_PATH = "E:\ESP-IDF\.espressif"
```

`IDF_TOOLS_PATH` is set permanently as a User environment variable.

### Minimal activation (new shells)

```powershell
$env:IDF_PATH = "E:\ESP-IDF\.espressif\v5.4.4\esp-idf"
$env:PATH = "E:\ESP-IDF\.espressif\tools\idf-exe\1.0.3;" + `
    "$env:IDF_PATH\tools;" + `
    "E:\ESP-IDF\.espressif\tools\cmake\3.30.2\bin;" + `
    "E:\ESP-IDF\.espressif\tools\ninja\1.12.1;" + `
    "E:\ESP-IDF\.espressif\tools\xtensa-esp-elf\esp-14.2.0_20260121\bin;" + `
    "$env:PATH"
```

On first use in a new shell, run `idf_tools.py export --format key-value` to sync PATH. The `idf.py.exe` loader (from idf-exe) must be on PATH for `idf.py` commands to work.

### Conda vs IDF Venv

- The IDF export script (`activate.py`, `export.ps1`) errors on missing venv — **ignore**, it is non-blocking.
- `idf.py` runs with conda's Python; the venv-not-found message is cosmetic.
- If `idf.py` refuses to run due to missing venv, use `python tools/idf.py` as fallback.

## Build Workflow

All `idf.py` commands run from the project directory (e.g. `src/esp32/wifi_tx/`).

```powershell
# full cycle
idf.py fullclean build flash

# step-by-step
idf.py set-target esp32       # once per project
idf.py menuconfig             # WiFi SSID/password
idf.py build
idf.py -p COM?? flash
idf.py -p COM?? monitor
```

### Common idf.py commands

| Command | Purpose |
|---------|---------|
| `idf.py set-target esp32` | Set target chip (Xtensa ESP32) |
| `idf.py menuconfig` | Graphical Kconfig configurator |
| `idf.py build` | Compile and link |
| `idf.py -p COM?? flash` | Flash via UART |
| `idf.py -p COM?? monitor` | Serial monitor (exit: Ctrl+]) |
| `idf.py -p COM?? flash monitor` | Flash then monitor |
| `idf.py clean` | Clean build artifacts |
| `idf.py fullclean` | Delete entire build directory |
| `idf.py reconfigure` | Rerun CMake without clean |
| `idf.py size` | Show firmware size breakdown |
| `idf.py erase-flash` | Erase entire flash |
| `idf.py uf2` | Generate UF2 firmware image |

### Environment shortcuts

```powershell
$env:ESPPORT = "COM3"       # default serial port
$env:ESPBAUD = "921600"     # flash baud rate
$env:IDF_CCACHE_ENABLE = 1  # enable compiler cache
```

## Project Structure Patterns

### Standard ESP-IDF project

```
project/
├── CMakeLists.txt          # project-level CMake (entry)
├── sdkconfig               # Kconfig generated config (do NOT hand-edit)
├── sdkconfig.defaults      # default config overrides (safe to edit)
├── main/
│   ├── CMakeLists.txt      # component registration
│   ├── Kconfig.projbuild   # custom Kconfig menu items
│   └── main.c              # application entry
└── build/                  # build output (do NOT hand-edit)
```

### This repo: `src/esp32/wifi_tx/`

```
wifi_tx/
├── CMakeLists.txt          # project entry
├── sdkconfig               # generated
├── sdkconfig.defaults      # default WiFi config etc.
├── main/
│   ├── CMakeLists.txt      # component: sources + idf_component_register
│   ├── Kconfig.projbuild   # WiFi SSID/PASSWORD menu
│   └── main.c              # SPI Slave + WiFi UDP
└── build/                  # autogenerated
```

## Core Rules

- Treat `main/CMakeLists.txt` as the source list authority. Add new source files there via `idf_component_register(SRCS ...)`.
- Do NOT hand-edit `sdkconfig` — change it via `idf.py menuconfig` or `sdkconfig.defaults`.
- Preserve `sdkconfig.defaults` and `Kconfig.projbuild` shape when adding new config items.
- Do not guess Kconfig symbol names; use `idf.py menuconfig` or grep `sdkconfig` for existing patterns.
- When adding dependencies (e.g. `COMPONENT_REQUIRES`), edit `main/CMakeLists.txt` not the project root.
- `idf.py` writes logs to stdout/stderr; parse return codes, not text.
- If `idf.py build` fails, scroll up past the error to find the real compile/link error.
- CMake version mismatch warnings from conda (4.1.1 vs IDF's preferred 3.30.2) are non-fatal; build still works.
- Keep the project's `main/` component self-contained; avoid creating extra components unless the design explicitly needs them.
- For SPI or other peripheral config, match the hardware pinout in `main.c` — not all pins are available on ESP32 DevKitC.

## Flash and Monitor

- Find COM port via Windows Device Manager (Ports) or `python -m serial.tools.list_ports`.
- Default flash baud: 460800. Use 921600 with `ESPBAUD` for faster flashing on stable USB-UART.
- Flash voltage: 3.3V. Do not use 5V on ESP32 GPIO.
- If flash fails repeatedly, hold BOOT button, press EN, release BOOT — standard ESP32 download mode.
- `idf.py monitor` accepts `--filter` for log level filtering, `--timestamp` for timing.

## K230 → ESP32 → WiFi Link

For the NUEDC project's image transmission pipeline:

- `main.c` configures SPI Slave with CS on GPIO15, MOSI GPIO13, MISO GPIO12, SCLK GPIO14.
- Received JPEG frames are forwarded via UDP to the notebook's IP:5000.
- WiFi config: `idf.py menuconfig` → "WiFi Configuration" → SSID/PASSWORD.
- The ESP32 runs in Station mode; the notebook runs a Python UDP receiver.

## Debugging

- Use `idf.py monitor --timestamp` with log level verbose (`CONFIG_LOG_DEFAULT_LEVEL_VERBOSE`) for detailed SPI/WiFi trace.
- If ESP32 resets in a loop, enable `CONFIG_ESP_SYSTEM_PANIC_PRINT_REBOOT` in menuconfig.
- Common crash reasons: stack overflow (increase `CONFIG_MAIN_TASK_STACK_SIZE`), WiFi OOM (check `CONFIG_ESP_WIFI_STATIC_RX_BUFFER_NUM`), SPI DMA buffer alignment.
- Enable `CONFIG_SPIRAM` if external PSRAM is populated and JPEG decode needs more heap.

## External Modules

When integrating sensors, displays, or modules:

- Ask for part number, datasheet, wiring, and I2C/SPI/UART pin mapping.
- Check GPIO availability against `references/hardware_pins.md`.
- Confirm logic level compatibility (ESP32 GPIO is 3.3V tolerant, NOT 5V).
- Verify power requirements: ESP32 peak current ~500 mA; budget for total system draw.
